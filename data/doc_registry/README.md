# Реєстр і кодифікація документів клієнтів (Google Диск → поля CRM)

## Що це

Файли в папках «Клієнти» та «Клієнти_клон» на Google Диску (600k+) розкладаються
за сегментами — **блоками справи** з каталогу полів CRM (`crm_fields_catalog.xlsx`, 26 блоків).
Кожен файл отримує код, а кожен тип документа звʼязаний з конкретними полями CRM,
які з нього має заповнити парсер.

| Код | Що означає | Приклад |
|---|---|---|
| `ZV-BB` | Блок справи (сегмент) | `ZV-14`: Кредитори та борг |
| `ZV-BB.TT` | Тип документа в блоці | `ZV-14.02`: Кредитний звіт УБКІ |
| `ZV-F-BB.NNN` | Поле CRM (блок поля + № у блоці) | `ZV-F-14.012` → `UF_CRM_…` |
| `ZV-BB.TT-КЛІЄНТ-NNNN` | Екземпляр документа | `ZV-14.02-K3F9A0B-0002`: другий звіт УБКІ клієнта |

`КЛІЄНТ` — стабільний ключ папки клієнта (`K` + 7 hex від ID папки). Файли, що лежать прямо в корені,
отримують ключ `R…`. Телефон з назви папки (`ПІБ, +380…`) зберігається окремо: за ним реєстр
стикується з контактом Bitrix24.

Блок `00` — службові файли: `00.01` скан без типу (потрібен OCR), `00.02` архіви / lock-файли,
`00.03` медіа, `00.04` робочі нотатки юриста, `00.05` звіти перевірки КЕП, `00.00` не розпізнано.


## Як класифікується файл

1. **Назва файлу**: регулярки типу документа, напр. `убкі|ubki|кредитн.* істор` → `14.02`.
2. **Назви папок**: найближча папка важить найбільше, напр. «УБКІ» → `14.02`, «Заява АК» → `18.x`,
   «Декларації» → `17.07`. Папка підтверджує тип із назви або сама визначає тип, коли назва
   неінформативна (`04.02.pdf`, `2024.docx`).
3. «Особисті документи» не задають тип, а лише звужують коло блоків (01–12).
4. Коли в назві є лише кредитор (`Мілоан 01.05.2025.pdf`), тип визначає папка, а без неї ставиться `14.07`.
5. Документи родичів (`паспорт + іпн матір`, `дохід сестра`) переносяться в `02.04` / `05.05`.
6. Якщо нічого не спрацювало, тип визначається за mimeType (`00.xx`) з впевненістю 0.2.

Додаткові ознаки в реєстрі: `creditor` (з довідника кредиторів), `subject` (боржник / родич),
`is_archived` (папки «старе», «не актуально»), `not_for_court` («Не в суд»), `needs_check` («ПЕРЕВІРИТИ_»),
`is_copy`, `is_duplicate` (той самий md5 у клієнта), `signed_container` (`.p7s` / `.asice`),
`also_contains` (комбіновані скани на кшталт «паспорт + іпн»), `sensitive` (ЕЦП, паролі: вміст не читати).

Ручне виправлення: рядок у `docs.doc_type_overrides (file_id, doc_type)` переважає правила при наступному запуску.

## Запуск

Сервісному акаунту (той самий JSON, що для Google Sheets, або окремий `GOOGLE_DRIVE_CREDENTIALS`)
треба дати доступ **«Переглядач»** на «Клієнти» та «Клієнти_клон». Якщо це Google Workspace,
можна натомість увімкнути domain-wide delegation і задати `GOOGLE_DRIVE_SUBJECT=info@zvilnymo.com.ua`.

```bash
psql "$DATABASE_URL" -f db/migrations/023_add_doc_registry.sql

# пілот без БД: 20 клієнтів з кожного кореня → Excel
python -m etl.gdrive.doc_registry_etl --no-db --limit-clients 20 --xlsx pilot.xlsx

# повний реєстр у PostgreSQL (≈ 600k файлів; 8 потоків, GDRIVE_WORKERS)
python main.py --mode doc-registry
# щоденний інкремент (файли, змінені після останнього завантаження)
python main.py --mode doc-registry-incremental
```

Повний запуск також видаляє з реєстру файли, яких більше немає на Диску. Робить це лише тоді,
коли обхід пройшов без помилок.

## Для парсера

```sql
-- що парсити і які поля CRM заповнити з кожного документа
SELECT doc_instance_code, doc_code, parse, file_id, crm_fields
FROM docs.vw_parse_queue
WHERE doc_code = 'ZV-14.02' AND confidence >= 0.8;

-- зведення по сегментах
SELECT * FROM docs.vw_registry_segments ORDER BY doc_code;
```

`parse`: `ocr` (скан / фото), `text` (docx / gdoc), `table` (xlsx / gsheet), `skip` (не парсити).
Черга не включає чутливі, архівні файли та дублі.

## Обмеження

* Класифікація йде за назвами файлів і папок, вміст не читається. Файли `00.01` / `00.00`
  (фото з телефона, `scan.pdf`) потребують другого проходу: OCR перших сторінок і ті самі регулярки
  по тексту.
* Блоки 03, 04, 06 (соцстатус, зайнятість, витрати) та частина типів блоків 02, 07, 08 не мають полів у CRM
  (див. «Полів-доказів = 0» в кодифікаторі). Документи реєструються, але парсити їх поки нікуди.
