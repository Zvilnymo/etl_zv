# Поля CRM → юридичний сенс

`crm_fields_legal_map.xlsx` — реєстр усіх полів Bitrix24 (ліди + угоди воронок Продаж / Підготовка до суду / Суд)
з поясненням для юриста: що фіксує поле, що воно доводить, з якого документа беруться дані і в який документ
справи про неплатоспроможність вони йдуть.

## Аркуші

| Аркуш | Що там |
|---|---|
| **Зведення** | кількість полів за ролями, за документами, рекомендації (паролі в CRM, порожні поля, дублі) |
| **Поля → юридичний сенс** | основний реєстр, 1 рядок = 1 код поля; фільтри по блоку, ролі, документу |
| **Документ → поля** | для кожного документа (Заява, Декларація, План реструктуризації, Опис майна, Перелік кредиторів, Процесуальні) — юридично значущі поля, відсортовані за блоком і заповненістю |
| **Довідник блоків** | 28 блоків справи: що доводять, первинні докази, куди йдуть, норма |

## Колонки основного реєстру

- **Блок справи** — особа, сім'я, доходи, витрати / ПМ, нерухомість, транспорт, рахунки, ФОП, судимість, правочини,
  кредитори, виконавчі провадження, судова справа, АК, представництво тощо.
- **Роль поля**:
  - *Доказ: скан первинного документа* — сам файл-доказ (додаток до заяви);
  - *Доказ: реквізити / відомості* — дані з документа для тексту («відповідно до … № … від …»);
  - *Розрахунок* — автоформули (дохід, витрати, ДЕЛЬТА, ДЕЛЬТА×60, сума до списання);
  - *Процесуальний трекінг* — номер справи, ухвали, строки;
  - *Контроль збору* — статуси чек-листа (самі не доказ);
  - *Скринінг* — відповіді клієнта на етапі продажу / з бота (не доказ, показують, що треба зібрати);
  - *Службове* — продаж, маркетинг, договір із компанією, системні поля;
  - *ЧУТЛИВЕ* — логіни / паролі / ЕЦП, які не мають зберігатися в CRM.
- **Що фіксує поле** — конкретний зміст саме цього поля.
- **Юридичне значення** — що це доводить у справі.
- **Первинний документ-доказ** — звідки береться (ДРРП, ГСЦ МВС, УБКІ, АСВП, ЄДР, ПФУ ОК-5/ОК-7, довідка МВС…).
- **✔ по документах** — куди йде поле.
- **Норма (орієнтир)** — КУзПБ / ГПК / СК; редакцію перевіряти на дату подання.
- **Рекомендація** — 0% заповнення, дублі назв, застарілі поля, чутливі дані.

## Оновлення

```bash
# з вивантаження аудиту (Google Sheet bitrix_field_audit → .xlsx)
python -m tools.crm_fields.build_catalog --audit-xlsx bitrix_field_audit.xlsx

# напряму з Bitrix24 (ліди, угоди, контакти, компанії, усі смарт-процеси; без % заповнення)
B24_DOMAIN=... B24_USER_ID=... B24_TOKEN_FIELDS=... python -m tools.crm_fields.build_catalog --from-b24
```

Юридичні описи живуть у `tools/crm_fields/legal_rules.py`:
`TOPICS` — блоки та їх сенс, `TOPIC_RULES` — правила за назвою поля, `CODE_PREFIX_TOPICS` — блок за смарт-процесом,
якщо назва поля нічого не каже («Статус», «Суд», «Дата»), `OVERRIDES` — ручні описи окремих полів.
Щоб уточнити опис поля, додайте / змініть запис в `OVERRIDES` і перезапустіть генерацію.
